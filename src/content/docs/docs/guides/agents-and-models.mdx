Sidequest runs whichever coding-agent CLIs you have installed. Claude Code is the default and the most deeply integrated; the others run quests through the same embedded terminal.

## Supported agents

| Agent | Binary | Permission flags Sidequest passes | Plan mode | Model flag | Effort |
|-------|--------|-----------------------------------|-----------|------------|--------|
| **Claude Code** | `claude` | `--permission-mode auto` (default) or `--dangerously-skip-permissions` | `--permission-mode plan` | `--model` | `--effort` |
| **Gemini CLI** | `gemini` | `--yolo` | `--approval-mode plan` | `-m` | none |
| **Codex CLI** | `codex` | `--dangerously-bypass-approvals-and-sandbox` (default) or `--approve-for-me` | `--sandbox read-only --ask-for-approval on-request` | `-m` | `-c model_reasoning_effort=...` |
| **Copilot CLI** | `copilot` | `--allow-all` | `--plan` | `--model` | none |
| **OpenCode** | `opencode` | none | none | `-m` | none |

Every agent runs inside tmux via your login shell, so tools installed with nvm, mise and the like are found. Sidequest auto-accepts the "trust this folder" prompts Claude Code, Codex and Copilot show on first launch in a directory.

### Codex permissions

Codex quests run without approval prompts or sandbox by default, like Claude Code with Auto Mode off: Codex's sandbox would block the `sidequest` commands agents use. To have Codex review its own approval requests inside its workspace-write sandbox instead, enable **Settings > Agent > Codex CLI > Approve for Me** (off by default). Councils follow the same setting; Codex supervisors always run unsandboxed.

### Shell

Pick **Shell** as the agent to get a plain terminal: your login shell in the quest's worktree or project checkout, depending on its **Type**. The prompt field becomes **Name (optional)**, and agent-only options (plan mode, context projects, attachments, GitHub issues, supervisor, **Advanced**) are hidden. Shell quests can't be handed off or supervised, and Changes panel comments don't apply. Shell is offered for quests only, not as the default agent.

### What only works with Claude Code

Several features read Claude Code's transcripts or rely on its hooks, so they apply to Claude Code quests only:

- The **smart router** and **Claude account profiles**
- **Auto Mode**, **Bypass Permissions in Home** and **Chrome Browser Tools** settings
- **Needs attention** status and notifications on this machine (via the Claude Code Stop hook; [remote quests](/get-sidequest/docs/advanced/remote-machines/#local-only-features) read it from the screen instead)
- **Automatic journals**, **Skip Auto-Journal** and **Handoff Quest**, and the "quest context" block injected at session start (other agents get the same context as plain prompt text, plus a hint about the `sidequest-journal` command)
- **Token statistics** in Live Stats and the Usage Dashboard, and **token budgets**

**Resume** works for Claude Code and Codex. When a Worktree or Review quest restarts without its tmux session (after **Restart Session**, a reboot, or starting a backlog quest that kept its worktree), Claude Code resumes the quest's own conversation and runs `/recap`, so the terminal opens on a summary of where it left off; Codex runs `codex resume --last` in the worktree. Either resumes only if it was also the agent of the quest's last run there. Other agents start fresh with the prompt.

Council briefings, journals, handoffs, the router and (as a fallback) branch naming use the `claude` binary themselves, so keep Claude Code installed even if your quests run on another agent. [Supervisors](/get-sidequest/docs/guides/supervisors/) can run on Claude Code, Codex, Copilot or OpenCode.

## Choosing the agent

- **Default**: Settings > Agent > **Default Agent** ("The AI coding agent to use for new quests. Can be overridden per-quest.")
- **Per quest**: the **Agent** select in the Create Quest dialog, or in Edit Quest while the quest is in Backlog. Changing the agent resets **Model** and **Effort** to Auto. If the quest kept its worktree from an earlier run, a different agent starts fresh on that code with the quest's prompt.
- **CLI paths**: each agent has a **CLI Path** field in Settings > Agent with a **Detected** / **Not found** indicator. Leave it blank to auto-detect.

## Permission modes (Claude Code)

| Setting | Effect |
|---------|--------|
| **Auto Mode** on (default) | `--permission-mode auto`: Claude Code's classifier approves routine actions and escalates risky ones |
| **Auto Mode** off | `--dangerously-skip-permissions`: nothing is checked |
| **Bypass Permissions in Home** | Only shown when Auto Mode is on. Home quests get `--dangerously-skip-permissions` because the classifier escalates constantly outside a repo |
| **Start in plan mode** (per quest) | `--permission-mode plan` |

Claude Code supervisors always run with `--dangerously-skip-permissions`.

## Models and effort

Open the collapsible **Advanced** section in the Create Quest or Edit Quest dialog. It holds **Token budget**, **Model** and **Effort**; Edit Quest opens it by itself when any of them is set.

**Model** is a searchable combobox. It groups **Recently used** models (the last five per agent), **Presets**, and for Codex and OpenCode a **Discovered** list read from the CLI itself. You can also type any model id; Sidequest passes it through as-is and warns that it is not a known model for this agent.

| Agent | List |
|-------|------|
| Claude Code | Presets: Fable, Opus, Sonnet, Haiku |
| Codex CLI | Discovered from `codex debug models` (falling back to Codex's `models_cache.json`) |
| Copilot CLI | Presets: GPT-5.4, Claude Sonnet 4.6, Claude Sonnet 5 |
| OpenCode | Discovered from `opencode models` |
| Gemini CLI | none -- type a model id |

Discovered lists refresh in the background when the picker opens and the list is empty or older than 12 hours; the **Refresh** row refetches on demand. A failed refresh keeps the cached list.

**Auto** is the default. For Claude Code with smart routing on it reads **Auto (smart router)**; otherwise **Auto (agent default)**, which simply omits the model flag.

**Effort** applies to Claude Code (`--effort`) and Codex (`model_reasoning_effort`); other agents ignore it.

- Claude Code's default is **Settings > Agent > Effort Level** (Low, Medium, High, Extra High, Max), itself defaulting to **Extra High**. The per-quest **Effort** select offers Auto (settings default), Low, Medium, High, XHigh, Max. Precedence: quest override > router decision > global setting.
- For Codex, **Auto (agent default)** leaves effort to Codex's own configuration. The select lists only the levels the chosen model supports (with model Auto, the levels every listed model supports), and switching to a model that lacks the current level resets it to Auto.

### Changing a quest's model or effort later

Edit Quest opens for backlog quests only. To change an active quest, **Move to Backlog** (keeping its worktree), click it, change the values and click **Make Active**. Effort applies the next time the session starts. A new model applies only to a fresh session: a resumed conversation keeps the model it started with.

## Smart model router

With smart routing on (the default), a Claude Code quest whose model is **Auto** is routed before its first session starts. Sidequest runs a quick, non-interactive `claude --print` call with the quest's type, plan-mode flag, title and description, and the [routing rules](/get-sidequest/docs/advanced/router-rules/) as the system prompt. It returns a model (`opus` or `sonnet`) and an effort level, and the quest launches with both. The quest card shows **Routing model...** during this step.

<Mermaid chart={`graph LR
  A[Quest: title + prompt] --> B[Router: claude --print, Sonnet]
  B -->|JSON model + effort| C[Launch quest session]
  B -->|timeout or error| D[Fallback model, medium effort]
  D --> C`} />

- The router itself always runs on Sonnet at low effort, so routing costs very little.
- If routing fails or takes more than 20 seconds, the quest launches on the **Fallback model** (Settings > Routing; Haiku, Sonnet or Opus, default Sonnet) at medium effort.
- Picking a model manually bypasses the router entirely and uses the global effort setting unless the quest overrides it.
- Routing happens only when a new session is created, not when a quest resumes.
- Supervisors never route; their **Auto** means the agent default.

The same rules file also decides which model Sidequest's own background jobs use -- handoff summaries, journal entries, Council briefings and the Claude fallback for branch names. See [Smart Router Rules](/get-sidequest/docs/advanced/router-rules/) to read or edit the rules.

Turn routing off with **Settings > Routing > Enable smart routing**. Quests then launch with no model flag, i.e. your Claude Code default.

## Claude account profiles

A **profile** is a separate Claude Code configuration directory (`CLAUDE_CONFIG_DIR`) under `~/.sidequest/profiles/<name>/`. Each profile holds its own credentials, settings and conversation history, so you can run some quests on a work account and others on a personal one. Skills, plugins, commands, agents and `CLAUDE.md` are shared with your main `~/.claude` by symlink.

### Adding a profile

1. Open **Settings > Agent > Claude Profiles**
2. Type a name in **Profile name** and click **Add profile**
3. A **Log in** dialog opens with an embedded terminal running `claude auth login` for that directory. Finish the login flow there and click **Done**

Each profile row shows the signed-in email and plan (or **Not signed in**) with **Log in** / **Switch account**, **Refresh** and **Delete** buttons. Deleting a profile removes its directory, including that account's conversation history; quests using it fall back to the default account.

### Using profiles

- **Per quest**: once at least one profile exists, Create Quest and Edit Quest show a **Claude account** select with **Default account** (your ambient `~/.claude`) and each profile. It can be changed while the quest is in Backlog; a quest moved to another account starts a fresh conversation, because the old one lives in the first account's directory.
- **Per project**: Project Settings > **Default Claude account** sets the account new quests in that project start on.
- The terminal header shows the profile name while a quest runs on one, and the Usage Dashboard includes every profile's transcripts.
